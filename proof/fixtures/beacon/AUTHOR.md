# Beacon fixture authorship

Beacon was authored independently without inspecting the sibling publisher or
the shared implementation. Only the fixture declaration and process protocols,
and the consumer CLI summary, were supplied by the coordinator.

Beacon treats documentation as an operator reference: command table, observed
example, boundaries, and operating notes. It uses TOML for a small exact
operations file and puts a behavioral contract in JSON beside a Markdown
fixture. The ordinary triage-links skill supports investigating extraction
errors; its linked reference and report asset belong to everyday consumer work.

standards.yaml is JSON text, a JSON-compatible YAML subset. Defaults supply five
independent declarations. Full inherits each declaration unchanged. Compact
replaces operations-record completely, dropping its guidance and readiness
check, and excludes contribution-governance. The shorter operations file is a
whole-file replacement, so the old capture section must disappear.

The publisher's scripts are named declaration-level operations only. They do
not adopt standards, resolve profiles, copy exact files, or author the README.
The local-link-contract repair writes two example files and its check executes
the real consumer to verify their relationship. Each invocation appends actual
argv, cwd, declaration, and selection context to .author-trace.jsonl. That trace
is execution evidence, not a fabricated transcript.
